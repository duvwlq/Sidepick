## 6. GitHub Issues 활성화 — 즉시 실행 가능

운영진 피드백 핵심: **"GitHub Issues 또는 Jira에 등록"**.
우리는 이미 GitHub 사용 중이므로 Issues 활성화 = 즉시 대응 가능.

### 6.1 라벨 체계

| 라벨 | 색 | 용도 |
|---|---|---|
| `P0` | 🔴 빨강 | 즉시 처리 (블로커) |
| `P1` | 🟡 노랑 | 이번 주 내 처리 |
| `P2` | 🟢 초록 | 다음 주 또는 추후 |
| `AI` | 🟣 보라 | AI 파트 |
| `BE` | 🔵 파랑 | BE 파트 |
| `PD` | 🌸 핑크 | PD 파트 |
| `bug` | 🔴 빨강 | 버그 |
| `feature` | 🟢 초록 | 신규 기능 |
| `discussion` | ⚪ 흰색 | 논의 필요 |
| `betatest` | 🟠 주황 | 베타테스트 발견 이슈 |

### 6.2 이슈 템플릿 (`.github/ISSUE_TEMPLATE/`)

**버그 리포트** (`bug.md`):
```markdown
## 버그 내용
(현상 1줄)

## 재현 경로
1. ...
2. ...
3. ...

## 기대 동작
(이렇게 동작해야 함)

## 실제 동작
(이렇게 동작함)

## 환경
- 브라우저: Chrome / Safari / 모바일
- 배포 URL:
- 캡처: 첨부

## 담당 (라벨 적용)
- [ ] AI / BE / PD
```

**기능 요청** (`feature.md`):
```markdown
## 기능 요약

## 필요 이유 (사용자/팀)

## 영향 받는 파트
- [ ] AI
- [ ] BE
- [ ] PD

## 우선순위
- [ ] P0 / P1 / P2

## 관련 문서
- PM-XX / AI-XX / BE-XX
```

### 6.3 워크플로우

```
[이슈 발생] (디스코드 또는 베타테스트)
    ↓
[GitHub Issues 등록] + 담당자 할당 + 라벨
    ↓
[처리 PR] (브랜치명에 issue 번호 포함, 예: feature/ai-issue-12)
    ↓
[리뷰 + 머지]
    ↓
[Issue Close] (PR 머지 시 자동 또는 수동)
```

→ **운영진이 원하는 "이슈 발생 → 공유 → 담당자 → 해결 → 검증"이 자동으로 박힘**.

## 7. 다음 라운드 발표 어필

심사위원에게 **이렇게 변화함을 어필**:

```
[Before MVP] 노션 회의록만 있음
   ↓
[After 운영진 피드백] 
- 노션 메인/아카이빙 분리 + 버전 표기
- GitHub Issues 활성화 → 이슈 트래킹 흐름 박힘
- 외부 도구 매트릭스 명시 (Figma / 디스코드 / LangSmith / RookieAILabs)
- 베타테스트 보고서 누적 + 엣지케이스 모음
- 사이드픽 차별화 페이지 4종 (에이전트 시스템 / 자산화 흐름 / 안전장치 / 분석 근거 모달)
```

→ "협업 흐름이 도구에 박혀 자동으로 증빙됨" 강조.
