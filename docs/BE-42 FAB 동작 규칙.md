# BE-42 FAB 동작 규칙

## 목적

이 문서는 W4 기준 FAB 버튼 구현 시 FE/BE가 맞춰야 할 최소 동작 규칙을 정리한다.
본 티켓은 FE 중심이지만, 라우팅과 비활성 조건을 공용 규칙으로 남긴다.

---

## 현재 기준

- 디자인 근거: `PD-30`
- 현재 FE 하네스에도 FAB 검토 규칙 존재
- 글 작성 화면에서 FAB가 방해되지 않아야 한다는 피드백이 반영돼야 한다

---

## FAB 상태

### 1. 기본 상태

- 우하단 고정 원형 버튼
- 클릭 시 확장 메뉴 노출

### 2. 확장 상태

- 메뉴 2개 노출
  - `AI 챗봇`
  - `경험 작성`

### 3. 비활성 상태

- 글 작성 중이거나 현재 화면에서 FAB가 방해되는 경우
- 회색 처리 및 클릭 막기

---

## 라우팅 규칙

- `AI 챗봇` 클릭 → 챗봇 화면 진입
- `경험 작성` 클릭 → 글 작성 화면 진입
- 현재 작성 화면에 있으면 `경험 작성` CTA는 비활성 상태로 본다

---

## UX 규칙

- 기본 상태에서 화면 주요 CTA를 가리지 않는다
- 확장 시 dim 또는 시선 집중 처리를 허용한다
- 글 작성 화면에서는 FAB를 숨기거나 비활성화해 입력 흐름을 깨지 않게 한다

---

## 완료 기준

- 기본/확장/비활성 3상태가 구분된다
- 챗봇/경험 작성 이동이 정상 동작한다
- 작성 중 FAB가 UX를 방해하지 않는다
