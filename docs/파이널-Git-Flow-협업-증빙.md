## 3. 브랜치 운영 전략 (Git Flow)

### 주요 브랜치

| 브랜치 | 용도 | 상태 |
|---|---|---|
| `main` | 배포 안정 브랜치 | 프로덕션 (side-pick.app) |
| `feature/ai` | AI 파이프라인·챗봇 개발 | 현재 활성 (파이널 대상) |
| `feature/backend` | 백엔드 API 개발 | main 병합됨 |
| `feature/fe-setup` | FE 초기 세팅 | main 병합됨 |
| `feature/ai-007-experience-detail` | 경험 상세 페이지 | main 병합됨 |
| `feature/update` | 업데이트 브랜치 | main 병합됨 |
| `Sidepick-merge-branch` | 릴리스 통합 | 6/24 릴리스 |
| `integration/release-validation` | 릴리스 검증 | 6/24 배포 |
| `codex/*` (7개) | AI 지원 개발 브랜치 | 병합·아카이브 |

### 브랜치 전략 요약

```
main (프로덕션)
  ├── feature/backend (BE 전용, main 병합됨)
  ├── feature/fe-setup (FE 초기, main 병합됨)
  ├── feature/ai (현재 활성 — 파이널 대상)
  │     └── ← ai/, fe/ 병렬 개발 트랙
  ├── Sidepick-merge-branch (릴리스 통합)
  └── integration/release-validation (배포 전 검증)
```

**핵심**: 파일 단위 격리 (`fe/`, `ai/`, `be/`) + 릴리스 병합 브랜치로 배포 안정성 확보.

## 10. 부록: Conventional Commits 준수

프로젝트 전체 커밋 형식:

- `feat(scope): 설명` — 68건 (신규 기능)
- `fix(scope): 설명` — 28건 (버그 수정)
- `docs(scope): 설명` — 43건 (문서화)
- `refactor(scope): 설명` — 10+ 건 (구조 개선)
- `chore(scope): 설명` — 20+ 건 (설정·의존)

**스코프 규칙**: `feat(fe)`, `feat(ai)`, `feat(be)`, `feat(faq)`, `feat(chatbot)` 등 명확한 도메인 구분.
