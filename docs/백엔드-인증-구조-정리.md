# 백엔드 인증 구조 정리

## 목표

- 인증 수단을 환경변수로 제어한다.
- 사용자 식별은 JWT와 `/api/users/me` 기준으로 통일한다.
- 로컬/운영에서 서로 다른 로그인 정책을 적용할 수 있게 유지한다.

## 현재 구조

### 인증 제공자 설정

인증 수단은 아래 환경변수로 제어합니다.

```env
APP_AUTH_LOCAL_ENABLED=<true|false>
APP_AUTH_KAKAO_ENABLED=<true|false>
APP_AUTH_GOOGLE_ENABLED=<true|false>
```

주의:

- `application.yml` 기본값은 `local=true`, `kakao=true`, `google=true` 입니다.
- 실제 동작은 `.env` 또는 배포 환경변수 override 결과를 따릅니다.
- 운영 문서에서 권장하는 값은 카카오만 활성화한 조합입니다.

### 서비스 구성

- `AuthService`
  - 인증 진입점 파사드
- `LocalAuthService`
  - 이메일 회원가입
  - 이메일/비밀번호 로그인
- `OAuthAuthService`
  - 카카오 로그인
  - 구글 로그인
  - 소셜 계정 연결 처리
- `EmailVerificationService`
  - 인증 코드 발급 및 검증
- `AuthTokenService`
  - Access/Refresh Token 발급
- `EmailVerificationMailService`
  - SMTP/SES 기반 인증 메일 발송

## 사용자 식별 방식

- 프론트는 `userId`를 직접 보내지 않습니다.
- 인증 후에는 JWT를 사용합니다.
- 사용자 정보 조회는 `/api/users/me` 기준입니다.
- 작성/수정/삭제 권한은 서버가 현재 인증 사용자 기준으로 판정합니다.

## 소셜 계정 연결 정책

- 소셜 로그인 성공 시 `social_accounts` 기준으로 기존 연결을 우선 조회합니다.
- 연결된 계정이 없으면 `users` 와 `social_accounts` 를 함께 생성합니다.
- 소셜 계정 사용자의 대표 인증 공급자는 `auth_provider` 로 관리합니다.

## 권장 운영 기준

운영 환경 문서 기준 권장값:

```env
APP_AUTH_LOCAL_ENABLED=false
APP_AUTH_KAKAO_ENABLED=true
APP_AUTH_GOOGLE_ENABLED=false
```

다만 이는 운영 권장값일 뿐이고, 로컬 개발에서는 이메일 로그인이나 구글 로그인을 켜서 테스트할 수 있습니다.

## 점검 포인트

- 카카오/구글 Redirect URI가 프론트 도메인과 일치하는지
- `APP_AUTH_*_ENABLED` 값이 현재 환경 의도와 맞는지
- `/api/users/me` 응답 구조가 프론트 세션 구조와 일치하는지
- 인증 실패 메시지가 프론트에서 처리 가능한 형태인지
