# BE-07 토큰 모니터링 명세

## 전달 산출물

- 대시보드 구조
- 자동 차단 정책

## 최종 결정 요약

1. 토큰 모니터링은 `user_token_usage` 집계 테이블과 `llm_request_logs` 상세 로그 테이블로 분리한다.
2. 사용자 한도는 `10,000 토큰/일`, `$0.50/일`로 둔다.
3. 서비스 전체 비용 cap은 `$5/일`로 둔다.
4. `80%` 도달 시 경고, `100%` 도달 시 ReAct 차단 후 Plan B만 허용한다.
5. ReAct 한도와 운영 로그는 LangSmith metadata와 DB 양쪽에서 추적한다.

## 팀장 확인 필요 항목

1. 사용자 일일 토큰 한도 `10,000` 확정
2. 사용자 비용 cap `$0.50`, 서비스 비용 cap `$5` 확정
3. `80% 경고 / 100% Plan B` 정책 확정
4. 관리자 대시보드는 간단한 버전만 이번 고도화 범위에 포함
5. BE가 직접 LangChain agent를 실행하지 않아도 DB 로그 테이블 선반영 확정

## 목적

에이전트 C의 비용 폭증과 발표 직전 한도 초과를 막기 위해 토큰 사용량 추적, 자동 차단, 운영 대시보드 기준을 확정한다.

## 관리 대상

- 사용자별 일일 토큰 사용량
- 사용자별 일일 비용
- 서비스 전체 일일 비용
- ReAct 반복 횟수
- 응답 시간
- fallback 발생 사유

## 데이터 구조

### 1. 집계 테이블: `user_token_usage`

역할:

- 사용자별 일일 누적치 저장
- 차단 여부 판단의 기준 테이블

핵심 필드:

- `usage_date`
- `user_id`
- `agent_type`
- `request_count`
- `input_tokens`
- `output_tokens`
- `total_tokens`
- `estimated_cost_usd`
- `fallback_count`
- `blocked_count`

### 2. 상세 로그 테이블: `llm_request_logs`

역할:

- 디버깅
- 대시보드 drill-down
- fallback 원인 분석

핵심 필드:

- `route_type`
- `model_name`
- `prompt_version`
- `tool_calls`
- `iterations`
- `fallback_reason`
- `response_status`
- `latency_ms`

## 정책값

| 항목 | 값 |
| --- | --- |
| 사용자 일일 토큰 한도 | `10,000` |
| 사용자 일일 비용 cap | `$0.50` |
| 서비스 일일 비용 cap | `$5.00` |
| max_iterations | `7` |
| 응답 시간 cap | `30초` |
| 입력 길이 제한 | `500자` |
| warn threshold | `80%` |
| block threshold | `100%` |

## LangSmith 연동 기준

- prefix: `LANGSMITH_*`
- endpoint: `https://apac.api.smith.langchain.com`
- project: `sidepick-agent-c`

적용 원칙:

1. BE가 LangChain agent를 직접 실행할 때만 BE 로컬 `.env`에 설정한다.
2. BE가 AI 서버만 호출하면 trace는 AI 서버 쪽에서 기록되므로 BE에 필수는 아니다.
3. `fallback_reason`, `route`, `tool_calls`, `iterations`는 trace metadata로 남긴다.

## 차단 정책

### 사용자 단위

1. `80%` 이상 도달
   - FE 경고 문구 노출
   - ReAct 요청 전 사전 안내 가능
2. `100%` 도달
   - ReAct 차단
   - Plan B만 허용
3. 비용 cap 초과
   - ReAct 차단
   - Plan B만 허용

### 서비스 단위

1. 일일 비용이 `$5` 근접 시 관리자 대시보드 경고
2. `$5` 도달 시 신규 ReAct 차단
3. Plan B와 캐시 응답만 허용

## 집계 로직

1. 요청 시작 시 사용자 정책 조회
2. 라우팅 결과가 Plan B면 저비용 경로로 처리
3. ReAct 수행 후 실제 토큰 사용량과 비용을 저장
4. `user_token_usage`를 upsert
5. `llm_request_logs`에 상세 1건 기록
6. 차단 조건 충족 시 다음 요청부터 정책 적용
