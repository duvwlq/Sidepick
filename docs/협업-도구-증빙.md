## 2. 노션 칸반 보드 운영

### 2.1 구조

```
사이드픽 워크스페이스
├── 📌 고도화 개발단계 전체 계획 (v6.1)
├── 📋 Task 티켓 1 (W1 — 5/18~5/24)

├── 📋 Task 티켓 3~6 (W3~W6 예정)

├── 📊 데일리스크럼 기록
└── 📊 베타테스트 보고서 (PD)
```

### 2.2 Task 티켓 형식 (표준화)

각 티켓은 동일한 구조로 작성:
- **주담당과정** (팀장 / AI / BE / PD)
- **진행 주차** (고도화 N)
- **진행 기간** (시작일 → 마감일)
- **진행 상태** (대기 / 진행 중 / 완료)
- **우선순위** (P0 / P1 / P2)
- **전달 파트** (의존 받는 파트)
- **상세 마감 일정 표** (티켓별 시작일 / 마감일 / 전달 대상 / 산출물 / 우선순위)
- **일자별 진행 일정**
- **의존성 관계**
- **작업 설명**
- **작업 완료 현황 (DoD 체크리스트)**
- **작업 완료** (산출물 링크 / 결과 메모)

## 3. 디스코드 협업

### 3.1 채널 구조

```
사이드픽 디스코드
├── #공지
├── #일반
├── #ai-파트
├── #be-파트
├── #pd-파트
├── #코드리뷰
├── #베타테스트
└── DM (보안 정보 — API 키 등)
```

### 3.2 협업 패턴

- **데일리 스탠드업**: 매일 오전 각자 채널에 "어제 한 일 / 오늘 할 일 / 블로커" 형식
- **수정 요청**: 파트별 채널에 [P0/P1/P2] 라벨 + 마감일 명시해서 전달
- **답변 회신**: 처리 완료 시 GitHub 링크 + 위치 (파일:라인) 함께 회신
- **민감 정보**: API 키 등은 절대 채널 X, DM으로만 전달

### 3.3 W1 마무리 사례 (PM-08 검수 대상)

팀장 → BE 디스코드 전달 6건 (5/23):

- [P0] business_categories.type 컬럼
- [P0] 16개 카테고리 INSERT
- [P1] BE-03 Swagger /api prefix
- [P1] BE-06 CategoryMapper slug↔한글

BE → 팀장 회신 (5/27): 각 항목별 처리 위치 + GitHub 링크 + commit hash 명시

## 4. GitHub Branch 전략 + PR 워크플로우

### 4.1 브랜치 구조

```
main
├── feature/ai        (AI 파트 — 팀장 작업)
├── feature/backend   (BE 파트)
└── feature/fe        (FE 파트, BE 통합)
```

### 4.2 Commit 컨벤션

```
<type>(<scope>): <subject>

<body>
```

- type: feat / fix / refactor / docs / chore
- scope: ai / pm / be / fe (선택)
- 예: `feat(ai): AI-07 failed.csv 패턴 완화 + 재정제 (+153건)`

### 4.3 W1~W2 commit 통계 (feature/ai 기준)

| 주차 | commit 수 | 주요 영역 |
|---|---|---|
| W1 (5/18~5/24) | 11 | PM 명세 / AI-01·03 / 환경 셋업 |
| W2 (5/25~5/27 현재) | 7 | AI-06~11 / PM-08·11 |
| **누적** | **18** | |

### 4.4 코드 리뷰

- feature 브랜치는 main에 머지 전 팀장 리뷰
- 본인 작업은 자체 리뷰 + 회귀 테스트 (syntax + import + 단위 동작 검증)

## 5. 데일리스크럼 + 스프린트 회고

### 5.1 데일리스크럼

- **빈도**: 매일 (목요일 제외)
- **형식**: 각자 디스코드 #일반에 작성
- **항목**: 어제 / 오늘 / 블로커
- **누적 기록**: RookieAILabs/사이드픽/daily_scrum_records.md (개인 백업)

### 5.2 스프린트 회고

- **빈도**: 주 1회 (금요일 배포 후)
- **형식**: 노션 회고 페이지
- **항목**:
  - Keep (계속 할 것)
  - Problem (개선 필요)
  - Try (다음 주 시도)
- **W1 회고 핵심 (5/24)**:
  - Keep: PM 명세 사전 정의로 BE/AI 작업 명확화
  - Problem: BE/AI 카테고리 정합성 (slug + 한글명 불일치) — 사전 합의 필요
  - Try: W2에선 BE에 카테고리 정합성 점검 미리 요청

### 5.3 베타테스트 보고서 (PD 담당)

PD가 매주 금요일 배포 후 베타테스트 진행 + 노션 보고서 작성:
- 기본 정보 (URL / 목표 / 참여자)
- 핵심 기능 테스트 (Happy Path)
- 버그 리포트 (심각도 / 담당자 / 상태)
- UX 피드백
- 다음 주 Action Item

## 7. 의존성 관리 + 인계

### 7.1 의존성 표기 (Task 티켓)

각 티켓에 "의존성" 명시:
- 다른 파트 산출물 (예: AI-07 → AI-08의 입력)
- 외부 데이터 (예: PD 설문 30건 → AI-08)
- 사전 정의 (예: PM-04 Tool 명세 → AI 시스템 프롬프트)

### 7.2 인계 패턴

- AI → BE: JSON 명세 + 디스코드 메시지 + GitHub 파일 링크
- BE → FE: API 명세 (Swagger) + 통합 테스트 코드
- PM → 전팀: 노션 정책 문서 + 디스코드 알림
