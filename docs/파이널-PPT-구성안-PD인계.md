## 1. 발표 전략 요약

### 심사평 7개 항목 반박 매트릭스

파이널 심사평에서 짚힌 항목마다 어떤 슬라이드로 대응할지 매핑:

| 심사평 지적 | 반박 슬라이드 |
|---|---|
| ① 문제 정의 정밀도 부족 | 슬라이드 3~5 (페르소나 + 시장 데이터) |
| ② 베타 정량화 부족 | 슬라이드 13~14 (3단계 사용자 검증) |
| ③ 가드레일 보완 필요 | 슬라이드 10~11 (Plan B 실작동) |
| ④ 성능 지표 미제시 | 슬라이드 12 (P50/P95) |
| ⑤ Git Flow 증빙 부족 | 슬라이드 15 (324커밋·100일) |
| ⑥ S3 보안 미흡 | 슬라이드 16 (인프라 완결성) |
| ⑦ 데모 안정성 우려 | 슬라이드 17~19 (실시간 시연) |

**핵심 서사**:
> "6→3명으로 축소된 팀이 100일 동안 3차 피벗을 감행해 5단계 AI 시스템을 완성.
>  60명 시장 조사 → 7명 베타 → 실사용 검증의 3단계 사용자 검증 완주."

### 4부: How · 기술 (심사평 ③ 반박) — 4장

#### 슬라이드 8 · 5단계 AI 아키텍처

**시각**: 5단계 다이어그램 (docs/파이널-5단계-AI-아키텍처.md의 Mermaid 렌더링)
**텍스트**:
```
【 5단계 AI 에이전트 시스템 】

[1] Intent Classification  → 부업 카테고리 자동 분류
[2] Retrieval              → SBERT + FAISS 383 벡터
[3] Generation             → Claude Sonnet 4.5 (RAG)
[4] Quality Guardrail      → 신뢰도 검증 + Plan B
[5] Delivery               → 근거 인용 + UI 렌더

▸ 3차 피벗 결과 (T5 폐기 → Claude 통합)
▸ 각 층에 실패 대응 폴백 라우트 내장
```
**발표자 노트**: "단순 파이프라인이 아닙니다. 각 층마다 가드레일이 내장된 설계입니다."

#### 슬라이드 9 · 기술 스택

**시각**: 아이콘 그리드 (React, FastAPI, Claude, Faiss, SBERT 등)
**텍스트**:
```

BE: Java Spring + FastAPI (하이브리드)
AI: Claude Sonnet 4.5 (`claude-sonnet-4-5`)
   임베딩: KR-SBERT-V40K (768차원)
   검색: FAISS IndexFlatIP (cosine)
데이터: 사례 136 + FAQ 247 = 383 벡터 통합 인덱스
인프라: AWS S3 + CloudFront + Amplify
```
**발표자 노트**: "국내 부업 도메인에 특화된 한국어 SBERT + 최신 Claude 조합. 소수 인원으로 대규모 스택 운영."
