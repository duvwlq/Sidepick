## 1. 개요

사용자 질문을 **단순 질문 → Plan B (단순 RAG)** / **복잡 질문 → ReAct** 로 자동 라우팅.
토큰 비용 관리의 핵심 — ReAct 발동 자체를 줄여서 비용 절감.

---

## 2. 라우팅 규칙

질문이 들어오면 아래 순서로 판정:

| 우선순위 | 조건 | 라우팅 결과 |
|---|---|---|
| 1 | 질문 길이 < 30자 | **단순 RAG (Plan B)** |
| 2 | 질문에 ReAct 키워드 포함 | **ReAct** |
| 3 | 그 외 (기본값) | **단순 RAG (Plan B)** |

### 2.1 ReAct 발동 키워드 리스트

질문에 아래 키워드 중 **하나라도 포함되면 ReAct**:

```python
REACT_KEYWORDS = [
    "비교",      # "스마트스토어 vs 블로그 비교해줘"
    "통계",      # "유튜브 부업 통계 알려줘"
    "유사",      # "내 경우랑 유사한 사례 찾아줘"
    "성공사례",  # "성공사례 보여줘"
    "실패사례",  # "실패사례 알려줘"
    "차이",      # "성공한 사람과 나의 차이가 뭐야?"
    "분석",      # "내 글 분석해서 알려줘"
    "추천",      # "어떤 부업이 나한테 추천돼?"
]
```

> 📝 키워드 리스트는 5주차 50개 시나리오 테스트 후 조정 가능.

---

## 3. 라우팅 흐름도

```
사용자 질문
    │
    ├─ 길이 < 30자? ──── YES ──→ 단순 RAG (Plan B)
    │
    NO
    │
    ├─ ReAct 키워드 포함? ── YES ──→ ReAct (멀티스텝)
    │
    NO
    │
    └─→ 단순 RAG (Plan B)
```

---

## 4. 토큰 한도 적용

| 라우팅 결과 | 일일 토큰 한도 | 비용 영향 |
|---|---|---|
| **단순 RAG** | 무제한 (또는 매우 높게) | 매우 적음 (Tool 호출 없음, 짧은 응답) |
| **ReAct** | 사용자당 10,000 토큰/일 | 높음 (LLM 5~7회 호출) |

- **사용자 입장**: 일상적 질문은 한도 차감 X / 진지한 상담만 한도 차감
- **비용 관점**: ReAct 호출 자체가 줄어들어 절약

---

## 5. 추가 안전장치

| 안전장치 | 값 |
|---|---|
| 사용자별 일일 비용 cap | $0.50/일 |
| 서비스 전체 일일 비용 cap | $5/일 |
| 입력 길이 제한 | 최대 500자 (FE + BE 양쪽 검증) |
| 한도 도달 시 동작 | ReAct 자동 차단 / Plan B만 동작 |
| 자동 차단 임계치 | 토큰 80% 도달 시 알람 / 100% 도달 시 Plan B 강제 전환 |

## 6. 예시 라우팅

| 질문 | 길이 | 키워드 | 결과 |
|---|---|---|---|
| "안녕" | 2자 | - | 단순 RAG |
| "유튜브 어때?" | 7자 | - | 단순 RAG |
| "스마트스토어 시작하려는데 조언 부탁해요" | 19자 | - | 단순 RAG |
| "스마트스토어 실패사례 보여줘" | 14자 | 실패사례 | 단순 RAG (길이 < 30자 우선) |
| "내 글이랑 비슷한 실패 케이스를 찾아서 비교 분석해줘" | 26자 | 비교, 분석 | 단순 RAG (길이 < 30자 우선) |
| "내가 작성한 스마트스토어 실패 경험을 바탕으로 비슷한 사례를 찾아서 분석해주세요" | 41자 | 분석 | **ReAct** |
| "스마트스토어와 블로그 부업의 성공률 통계를 비교해서 알려주세요" | 33자 | 비교, 통계 | **ReAct** |

> ⚠️ 길이 < 30자 조건이 키워드 조건보다 우선. 짧은 질문은 무조건 단순 RAG.
