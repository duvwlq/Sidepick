## 1. 개요

ReAct 루프가 실패할 경우 **단순 RAG fallback**으로 자동 전환하는 안전장치.
4주차 BE/AI 양쪽에서 구현되므로 구현 전 사전 정의 필수.

> ReAct 패턴은 질문 1회당 LLM을 5~7번 호출 → 토큰 비용 폭발 위험.
> 발표 직전 API 한도 초과 = 최악의 시나리오 → Plan B로 방어.

---

## 2. Plan B 트리거 5가지 조건

| # | 조건 | 동작 | 사용자 안내 | 예상 빈도 |
|---|---|---|---|---|
| 1 | `max_iterations` 초과 (7회 도달) | 마지막 Tool 결과 + 단순 응답 | ❌ 안내 X | 중간 (10~20%) |
| 2 | Tool 결과 0건 | 기본 템플릿 응답 | ✅ "비슷한 사례 없음" | 낮음 (5~10%) |
| 3 | LLM 응답 파싱 실패 | 재시도 1회 → 단순 RAG | ❌ 안내 X | 매우 낮음 (1~3%) |
| 4 | 응답 타임아웃 (30초 초과) | 즉시 RAG fallback | ✅ "시간이 더 필요" | 낮음 (3~5%) |
| 5 | Tool 호출 API 에러 | 재시도 1회 → ReAct 중단 | ❌ 안내 X | 매우 낮음 (1~3%) |

**Plan B 발동 합계 예상**: 약 20~40% (정상 ReAct = 60~80%)
→ 이 비율이 너무 높으면 ReAct 자체 품질 문제. **4주차 50개 시나리오 테스트에서 측정**.

## 3. 조건별 상세 명세

### 3.1 조건 #1 — `max_iterations` 초과

| 항목 | 내용 |
|---|---|
| **조건** | ReAct 루프가 `max_iterations=7`에 도달 |
| **동작** | ① 마지막 Tool 호출 결과 사용 ② 단순 LLM 응답으로 답변 생성 (1회 호출만) ③ 사용자에게 자연스럽게 답변 표시 |
| **사용자 안내** | 없음 (백엔드만 인지) |
| **로그 형식** | `fallback_reason: iterations_exceeded` |
| **추가 소요 시간** | 약 3~5초 |

### 3.2 조건 #2 — Tool 결과 0건

| 항목 | 내용 |
|---|---|
| **조건** | `search_cases(query)` 반환 = `[]` |
| **동작** | ① ReAct 루프 즉시 중단 ② 기본 응답 템플릿 사용 (업종별 일반 가이드) ③ 사용자에게 명시적 안내 |
| **사용자 안내** | ✅ "비슷한 사례를 찾지 못했어요. 일반적인 가이드를 안내드릴게요." |
| **로그 형식** | `fallback_reason: tool_empty_result` |
| **추가 소요 시간** | 약 2초 |

### 3.3 조건 #3 — LLM 응답 파싱 실패

| 항목 | 내용 |
|---|---|
| **조건** | LLM 응답을 ReAct 파서가 인식 못함 (JSON 깨짐, 형식 오류) |
| **동작** | ① 같은 prompt로 1회 재시도 ② 재시도도 실패 시 단순 RAG fallback ③ 사용자에게 자연스럽게 답변 표시 |
| **사용자 안내** | 없음 (백엔드만 인지) |
| **로그 형식** | `fallback_reason: llm_parse_error (retry: 1)` |
| **추가 소요 시간** | 약 5~8초 |

### 3.4 조건 #4 — 응답 타임아웃 (30초 초과)

| 항목 | 내용 |
|---|---|
| **조건** | 전체 응답 생성이 30초 초과 |
| **동작** | ① ReAct 진행 즉시 중단 ② 5초 내 단순 RAG로 답변 생성 ③ 사용자에게 명시적 안내 |
| **사용자 안내** | ✅ "응답 생성에 시간이 더 필요했어요. 간단히 안내드릴게요." |
| **로그 형식** | `fallback_reason: timeout` |
| **추가 소요 시간** | 35초 이내 답변 보장 |

### 3.5 조건 #5 — Tool 호출 자체 실패 (API 에러)

| 항목 | 내용 |
|---|---|
| **조건** | FAISS / 통계 API에서 5xx 에러 / 네트워크 타임아웃 |
| **동작** | ① 동일 Tool 1회 재시도 (0.5초 대기 후) ② 재시도도 실패 시 ReAct 중단 ③ 단순 LLM 응답으로 fallback |
| **사용자 안내** | 없음 (백엔드만 인지) |
| **로그 형식** | `fallback_reason: tool_api_error (retry: 1, tool: faiss)` |
| **추가 소요 시간** | 약 1~3초 |

## 4. 단순 RAG fallback 동작

Plan B 발동 시 사용하는 단순 RAG 흐름:

```
사용자 질문
  ↓
FAISS 검색 (단일 호출, Tool 없이)
  ↓
검색 결과 + 질문 → LLM 단일 호출
  ↓
응답 반환 (case_id 인용 포함)
```

- **LLM 호출 횟수**: 1회 (ReAct는 5~7회)
- **응답 시간**: 3~5초 (ReAct는 15~30초)
- **토큰 사용량**: ReAct의 약 1/5
- **품질**: 멀티스텝 추론은 불가하지만 "유사 사례 기반 안내"는 가능
