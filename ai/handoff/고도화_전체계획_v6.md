## 1. 고도화 수행 계획 개요

### AI / 콘텐츠
- 실패패턴 그래프 ("나와 같은 실수를 한 사람 X%") — 기존 칩에서 변경
- 실패 시점 분포 시각화
- 업종별 통계 페이지 + 실패 요인 TOP3
- 내 분석 결과 히스토리
- 성공사례 추가 (원글 + AI 분석글 / 나와 다른 점 비교)
- 부업 시작 전 실패 조심 안내 (성공 요인 부족 감지 → 유사 실패사례 연결)
- 부업 가이드 페이지 (검색창 + 업종별 카테고리 + 가이드라인)

### AI 에이전트
- **[에이전트 A] 글 작성 보조 에이전트** — 초안 분석 후 부족한 정보를 질문 카드로 수집, 보완된 정보로 더 정밀한 분석 실행
- **[에이전트 B] 리포트 자기검증 루프** — AI 분석 신뢰도 < 0.7 발동 / 재생성 1회 / 결과 캐싱
- **[에이전트 C] 부업 상담 에이전트** — Tool 2개 (FAISS 통합 검색 + 통계 조회), LangChain ReAct 루프로 멀티스텝 실행 / Plan B: ReAct 실패 시 단순 RAG fallback
- **[에이전트 D] 프로액티브 알림 에이전트 — v2.1로 이동** (런칭 후 사용자 데이터 누적 후 진행)

### 유저 경험
- 회원가입 상세항목 (성함·생년월일·성별·거주지·가입목적·닉네임·부업 경험여부)
- 소셜 로그인/가입 (네이버·카카오·구글)
- 관심 부업 선택 → 메인 홈 개인화 노출
- 북마크/저장
- 공감/반응 버튼 ("나도 이런 실수 했어요")
- 내 글 수정
- 경험 등록 시 사진 첨부 (썸네일 노출)
- 프로필 사진 등록
- 마이페이지 (닉네임·비밀번호·경험여부 변경 / 내 글·AI 분석 보기)
- 사례 검색 페이지
- 좋아요·댓글 알림
- 실패사례 → 성공사례 연결 버튼
- SNS 공유 (내 분석 결과 카드)
- 비회원 정책: 챗봇 비활성화 (회원만 사용)
- PII 자동 마스킹 (챗봇 로그)

### UI / 디자인
- 가이드형 글쓰기 (예시 텍스트 제공, 구조화된 입력 방식)
- FAB 버튼 (글쓰기·챗봇, 우하단 동그라미 형태, 글 작성 중 비활성화)
- 유사사례 좌우 분할 (왼쪽 성공사례 / 오른쪽 실패사례)
- 성공·실패 카드 1개씩 노출
- 브랜드 컬러 확정 + 전체 디자인 개편 (현재 모노톤 → 컬러 적용)

### 역할 분배
- **팀장**: PM 전체 (기획·일정·산출물 관리·QA)
- **AI**: AI 구현 전체 (에이전트·데이터 가공·분석글·추천 로직) + FE 일부 (실패→성공 버튼, 브랜드 컬러 FE 적용)
- **PD**: 전체 디자인 + 베타테스트 전담
- **BE**: 클라우드 + BE + FE 대부분 + 큐잉 인프라 + 가드레일

> 팀장과 AI는 동일 인물(오혜림)이 담당하며, 파트 구분은 업무 성격 기준

## 2. 에이전트 C 운영 안전장치 (v6 업데이트)

> **P0 — 반드시 챙겨야 할 것들**
> ReAct 패턴은 질문 1회당 LLM을 5~7번 호출 → 토큰 비용 폭발 위험
> 발표 직전 API 한도 초과 = 최악의 시나리오

| 항목 | 내용 |
|---|---|
| **Tool 수** | 2개 (search_cases 통합 + query_stats) / 성공사례는 type 필터링으로 통합 |
| **토큰 한도** | 유저당 일일 한도 10,000 + 하이브리드 라우팅 |
| **루프 제한** | max_iterations = 7 (50개 테스트로 최적값 확정 예정) |
| **응답 시간** | 30초 + 스트리밍 응답 (SSE) |
| **모델 분리** | 발표 전까지 Haiku vs Sonnet 비교 테스트 후 결정 |
| **캐싱** | DB 답변 캐시 (통계 7d / 사례 24h) + Prompt Caching |
| **Plan B** | 5가지 조건 명확히 정의 |
| **모니터링** | LangSmith 무료 티어 + 일일 토큰 사용량 대시보드 |
| **Tool 실패** | 재시도 1회 + Plan B 자동 전환 |
| **대화 방식** | 단일턴 + "페이지를 나가면 이전 대화를 기억하지 못합니다" 안내 |
| **한국어 튜닝** | 시스템 프롬프트 + Tool 설명 한국어 + 50개 시나리오 테스트 |
| **자동 차단** | 80% 자동 차단 / 100% Plan B만 동작 |
| **시연 안정성** | 4~5개 질문 사전 캐싱 |
| **가드레일** | 입력 (BANNED_WORDS) + 출력 (LLM 응답 필터) + 카테고리 화이트리스트 |
| **입력 길이** | 최대 500자 |
| **동시성** | BE 요청 큐잉 (Spring BlockingQueue) + "잠시만 기다려주세요" UX |
| **비용 cap** | 사용자별 일일 $0.50 + 서비스 전체 일일 $5 |
| **타임존** | KST 자정 리셋 + 사용자 노출 KST |
| **모델 ID 분리** | 환경 변수 `CLAUDE_MODEL`로 관리 |

### Tool 호출 방식 — 최종 결정
```
Tool 1: search_cases(query, type="failure" or "success", limit=3)
        → FAISS 통합 인덱스, type 메타데이터로 필터링
Tool 2: query_stats(category, metric)
        → 업종별 통계 / 실패 요인 TOP3

총 2개 Tool
```

**+ 성공사례 데이터 구조 설계 시 실패와 비슷한 스키마로 맞추기**
- 공통 필드: 원글 / 업종 / 기간 / 투자금 / 키워드 / AI 분석 / 메타 grid
- type별 추가:
  - failure: 실패 패턴, 핵심 이슈 칩
  - success: 성공 요인, 나와의 차이점

### 토큰 한도 — 하이브리드 라우팅
**[단순 질문] = Plan B (단순 RAG) 자동 라우팅**
- 일일 한도: 무제한 (또는 매우 높게)
- 비용 매우 적음 (Tool 호출 없음, 짧은 응답)

**[복잡 질문] = ReAct (멀티스텝)**
- 일일 한도: 10,000 토큰 유지
- ReAct 발동 자체를 줄여서 비용 관리

**라우팅 규칙**:
- 질문 길이 < 30자 → 단순 RAG (Plan B)
- 질문에 "비교", "통계", "유사", "성공사례" 키워드 포함 → ReAct
- 그 외 → 단순 RAG

### Plan B 트리거 조건별 동작 (5가지)

| # | 조건 | 동작 | 사용자 안내 | 빈도 예상 |
|---|---|---|---|---|
| 1 | max_iterations 초과 (7회 도달) | 마지막 결과 + 단순 응답 | ❌ 안내 X | 중간 (10~20%) |
| 2 | Tool 결과 0건 (FAISS 검색 0건) | 기본 템플릿 응답 | ✅ "비슷한 사례 없음" | 낮음 (5~10%) |
| 3 | LLM 응답 파싱 실패 (JSON 깨짐) | 재시도 1회 → 단순 RAG | ❌ 안내 X | 매우 낮음 (1~3%) |
| 4 | 응답 타임아웃 (30초 초과) | 즉시 RAG fallback | ✅ "시간이 더 필요" | 낮음 (3~5%) |
| 5 | Tool API 에러 (네트워크) | 재시도 1회 → ReAct 중단 | ❌ 안내 X | 매우 낮음 (1~3%) |

**Plan B 발동 합계 예상**: 약 20~40% (정상 ReAct = 60~80%) — 4주차 50개 시나리오 테스트로 실측 예정

## 3. 추가 위험 요소 결정 사항 (v6 신규)

### 가드레일
- **입력 가드레일**: BANNED_WORDS 필터링 → 차단 시 "부적절한 표현 포함" 안내
- **출력 가드레일**: LLM 응답 BANNED_WORDS 필터링 → 차단 시 재생성
- **카테고리 화이트리스트**: 시스템 프롬프트 + 응답 파싱 검증 + 재생성 (3중 방어)

### 개인정보 보호
- 챗봇 로그에 PII (실명/연락처) 자동 마스킹
- DB 저장 전 정규식으로 전화번호/이메일/주민번호 마스킹

### 모델 버전 관리
- 환경 변수 `CLAUDE_MODEL`로 분리 (예: `claude-sonnet-4-6`)
- 환경별 다른 모델: dev=Haiku / prod=Sonnet

### 시스템 프롬프트 버전 관리
- `prompts/agent_c_v{N}.md` 파일로 저장
- Git commit으로 변경 이력 관리
- 환경 변수 `PROMPT_VERSION`으로 선택

### 테스트 환경 — Mock → Haiku → Sonnet 3단 전략
1. **개발 초기**: Mock 모드 (USE_MOCK_LLM=true) → 비용 0원
2. **통합 테스트**: Haiku → 비용 1/5
3. **운영**: Sonnet → 정확도 ↑
- 개발용 별도 API 키 + 일일 한도 $5

### 시스템 프롬프트 구조 (페르소나 영향 분리)
- **Section 1 (Tool 선택)**: 페르소나 없이 기능적 지시
- **Section 2 (응답 생성)**: "선배의 조언" 페르소나 적용
- → Tool 선택 정확도 유지 + 응답 톤 통일
