# 핵심 Q&A 12개

## 1. "Claude API에 너무 의존한 것 아닌가요?" / "바이브코딩 아닌가요?" ⭐

**답변**:
> "5단계 중 1단계 원인 분석에서만 LLM 추론 도구로 활용했습니다.
> 매칭은 SBERT + FAISS로 **자체 구현**했고, advice 조합 로직과 49 매트릭스는 BE 로직 기반으로 **별도 LLM 호출 없이 자체 설계**했습니다.
> 사실 AI 강사님께서 직접 '바이브코딩 우려'를 지적해주셔서, 그 피드백을 받아 **5단계 시스템 전체를 자체 설계하는 방향으로 피벗**한 결과입니다."

**핵심 키워드**: 1단계만 / 자체 구현 / 자체 설계 / 강사님 직접 지적 → 피벗

---

## 2. "49건 데이터로 충분한가요?"

**답변**:
> "초기 49건에서 **100건으로 확장**했고, 외부 데이터 수집 서비스 100건도 추가했습니다.
> 자동 태깅 + JSON 검증 파이프라인을 구축했고, **v2에서 SBERT + FAISS API 확장과 함께 데이터셋도 확대**할 예정입니다."

**핵심 키워드**: 100건 확장 / 외부 서비스 / 자동 태깅 / v2 확장

---

## 3. "T5는 왜 폐기했나요?"

**답변**:
> "T5는 fine-tuning 학습 데이터가 부족해 한계가 명확했습니다.
> AI 강사님 멘토링에서 **크롤링은 자료 수집용으로만 활용하고, 유사 사례 매칭은 임베딩 모델 학습을 추천**받았고, 매칭에는 SBERT가 더 적합하다고 판단했습니다.
> **도구 선택의 의사결정 자체가 학습 과정이었습니다.**"

**핵심 키워드**: 학습 데이터 부족 / 강사님 멘토링 / 도구 선택 학습

---

## 4. "왜 카카오 로그인만 지원하나요?"

**답변**:
> "MVP 단계에서 **진입 장벽 최소화** 목적입니다.
> 국내 사용자 접근성이 가장 높은 OAuth로 카카오를 선택했고, 이후 **구글 소셜 로그인도 추가**했습니다.
> 추후 v2에서 애플 로그인 등도 확장 예정입니다."

**핵심 키워드**: 진입 장벽 최소화 / 카카오 + 구글 / v2 확장

---

## 5. "북극성 지표 1,000명은 어떻게 측정하나요?"

**답변**:
> "현재는 자체 가설 단계입니다.
> v2에서 **GA 또는 자체 분석 도구를 연동**해 탐색 → 경험 입력 → 분석 결과 확인까지 완료한 사용자를 측정할 계획입니다.
> 함께 재방문율(Retention) 30%, 사례 등록 전환율 15%, AI 가이드 만족도 4.5/5.0도 측정 예정입니다."

**핵심 키워드**: 자체 가설 / GA 연동 / v2 측정 / 보조 지표 3개

---

## 6. "FE는 누가 했나요? 정근원이 BE인데?"

**답변**:
> "프론트엔드는 팀장인 제(오혜림)가 주도하고, BE 담당 정근원 팀원이 통합 작업에서 일부 FE 작업을 함께했습니다.
> **인원 축소 상황에서 각자 역할을 확장한 사례**입니다.
> 오혜림: AI 전체 + PM + FE 일부 / 정근원: BE + 클라우드 + FE / 이은성: PD + PM"

**핵심 키워드**: 팀장 주도 + 협업 / 역할 확장 / 인원 축소 대응

---

## 7. "팀원 변동이 잦았는데 어떻게 일정 맞췄나요?" ⭐

**답변**:
> "**6명 → 5명 → 4명 → 3명**으로 줄어들었지만, PM 강사님께서 '포트폴리오 관점으로 강화하라'고 조언 주신 후, **각자 역할을 확장**했습니다.
> 오혜림: AI 전체 + PM + FE 일부 / 정근원: BE + 클라우드 + FE / 이은성: PD + PM
> Code Freeze를 일정 연장해서 UX 피드백 디테일 반영 시간도 확보했습니다."

**핵심 키워드**: 인원 변동 / 역할 확장 / 강사님 조언 / Code Freeze 연장

---

## 8. "중간점검 후 피드백을 어떻게 반영했나요?" ⭐

**답변**:
> "**5개 영역 강사님 서면 피드백**을 받고, 가장 큰 변화는 **서비스 방향성 피벗**입니다.
> 사례 공유 메인에서 **조회·검색 중심**으로 전환했고, 글쓰기를 **4단계 → 3단계, 자율서술 50자 → 10자**로 단순화했습니다.
> 또한 PD 강사님 1:1 멘토링에서 챗봇 vs Q&A 게시판 형태를 논의했고, **FAQ 게시판 형태로 결정**했습니다."

**핵심 키워드**: 5개 영역 서면 피드백 / 서비스 피벗 / 글쓰기 단순화 / FAQ 게시판

## 9. "v2 일정과 측정 계획은?"

**답변**:
> "**v2 우선 반영 11건 + 고도화 2건** 정리되어 있습니다.
> 우선 반영: 사용성 5건 / AI 품질 2건 / UI 4건
> 고도화: 사진 첨부 / 실패 패턴 그래프 / Q&A 큐레이션 / AI 가드레일 Python / SBERT+FAISS API 확장
> 북극성 지표 '탐색 후 의사결정 완료 사용자 수'를 GA 또는 자체 분석 도구로 측정 예정입니다."

**핵심 키워드**: 11건 + 2건 / 측정 도구 연동 / v2 가설 검증

---

## 10. "BM 단기/중기/장기 실현 가능성?"

**답변**:
> "현재는 **트래픽 확보 단계**(Phase 1)입니다.
> 무료 탐색 + AI 분석으로 사용자 유입을 극대화하고, 다음 단계에서 **구조화된 실패 사례 DB로 데이터 자산화**(Phase 2),
> 그 다음은 **B2B 실패 패턴 데이터 API 판매·컨설팅 + B2C 프리미엄 심층 분석 리포트 구독**(Phase 3)으로 수익화 예정입니다.
> v2에서 사용자 가설 검증 후 단계적으로 진행합니다."

**핵심 키워드**: 3단계 BM / 데이터 자산화 / B2B + B2C / 가설 검증

---

## 11. "AI 가이드 49개가 너무 적지 않나요?"

**답변**:
> "MVP 검증 단계로 **7개 부업 카테고리 × 7개 실패 패턴 = 49개**로 시작했습니다.
> 사이드픽이 **직접 작성한 자체 IP**입니다.
> v2에서 사용자 데이터가 누적되면 **advice 동적 추천 + 매트릭스 확장** 예정입니다."

**핵심 키워드**: 7×7 = 49 / 자체 IP / 동적 추천 확장

## 12. "실제 베타테스트 결과는?"

**답변**:
> "SNS 설문 **13명** + 지인 베타테스트로 4개 핵심 피드백을 도출했습니다.
> 1) 카테고리 선택지 추상적 → **구체화**
> 2) 글쓰기 50자 부담 → **10자로 완화**
> 3) 사진 첨부 요청 → **v2 고도화로 보류**
> 4) 시간/기간 입력 방식 한정적 → **다이얼식으로 변경**
> + '모르겠음' 옵션 추가 및 매출 단위(월/연) 표기까지 모두 반영했습니다."

**핵심 키워드**: 13명 / 4개 핵심 피드백 / 모두 반영

# 까다로운 질문 대응 전략

## A. "서비스의 메리트가 부족하지 않나요?"
> "PD 강사님께서도 같은 우려를 지적해주셨습니다.
> MVP는 핵심 기능 3가지(탐색·상세·입력)에 집중했고, v2에서는 **사용자 데이터 누적 후 advice 동적 추천 + 성공 사례 매칭으로 메리트를 강화**할 계획입니다."

## B. "초기 데이터 확보가 어렵지 않나요?"
> "외부 데이터 수집 서비스 100건 + 자체 크롤링 + 자체 매트릭스 49개를 활용했습니다.
> 사용자가 자신의 경험을 등록하면 그 자체가 데이터 자산이 되는 **순환 구조**로 설계했습니다."

## C. "디자인이 부족해 보이는데요?"
> "콘텐츠 중심 미니멀 UI에 '선배의 조언' 보이스톤을 의도적으로 적용했습니다.
> v2에서 실패 패턴 그래프 시각화 등 디테일을 강화할 예정입니다."

## D. "왜 다른 부업 정보 사이트와 다른가요?"
> "기존 커뮤니티/블로그는 **정성적·파편화**되어 비교 불가능하고, 유료 컨설팅은 접근성이 낮습니다.
> 사이드픽은 **정량적·구조화된 데이터, 무료 접근성, 실패 사례 중심**으로 차별화됩니다.
> 특히 **49 매트릭스 기반 AI 가이드 + SBERT+FAISS 유사 사례 매칭**이 핵심 차별점입니다."

## E. "발표자료 PPT를 강사님께서 검토하셨나요?"
> "각 파트 강사님께 사전 피드백을 받았고, 중간점검 발표 후 서면 피드백을 반영했습니다.
> PM이 없어서 기획 측면이 부족하다는 지적도 받았는데, **포트폴리오 관점에서 각 파트 강화**라는 조언을 받아 진행했습니다."

## F. "프로젝트가 실제 런칭 가능한가요?"
> "이미 운영 환경에 100% 안정화되어 있고(side-pick.app, 헬스체크 status: UP), 보안 체크리스트 5종 100% 이행 상태입니다.
> 3차 배포를 진행했고, 시연 시드 데이터로 안정성 검증도 끝났습니다.
> MVP 단계로는 충분히 운영 가능한 상태입니다."
