### [p1~3] 표지 + 사업 개요 + Index (15초)

> 안녕하세요. **실패를 자산으로 바꾸는 부업 실패 분석 서비스, 사이드픽** 팀 오혜림입니다.
> 저희는 부업 실패 사례를 구조화해 조회하고 AI로 분석하는 서비스를 만들었습니다. 오늘 5개 챕터로 말씀드리겠습니다.

### [p4] 시장 분석 (25초)

> 먼저 시장입니다. 통계청 기준 **부업 인구는 54만 5천 명**, 30대 증가율은 **16.8퍼센트**로 빠르게 커지고 있습니다.
> 그런데 저희 자체 설문 13명 중 **77퍼센트가 "실패 사례를 찾아봤지만 형식이 제각각이라 비교가 어렵다"**고 답했습니다.
> 시장은 커지는데, **실패 정보는 흩어져 있는 상황**입니다.

---

### [p5] 문제 정의 (20초)

> 문제는 세 가지입니다. **정보의 파편화**, **구조적 분석의 부재**, **의사결정 기준의 부재**.
> 개인의 시행착오가 공동의 자산이 될 수 있음에도, 분석 도구가 없어 단순한 푸념으로 끝나고 있습니다.

---

### [p6] 페르소나 (15초)

> 타겟은 두 명입니다. **박윤지 27세**는 실패 후 재도전하려는 사용자, **박현우 32세**는 시작 전 리스크를 미리 확인하려는 사용자입니다.

---

### [p7] Solution 3축 + 차별점 ⭐ (30초)

> 사이드픽의 해결책은 **사용자가 부담 없이 탐색하는 솔루션 3축**입니다.
> **정량화된 데이터로 탐색**하고, **AI 유사도 기반 매칭으로 비교**하고, **맞춤형 가이드로 의사결정**합니다.
> 커뮤니티는 정성적이고 광고성 정보가 혼재되며, 유료 컨설팅은 접근성이 낮습니다.
> 사이드픽은 **정량적·구조화 데이터, 무료 접근성, 실패 사례 중심**으로 차별화됩니다.

---

### [p8] 핵심 기능 3가지 (20초)

> MVP는 핵심 기능 세 가지에 집중했습니다.
> 실패 사례를 **빠르게 발견하는 탐색**, **한눈에 파악하는 상세 조회**, **재도전 인사이트를 도출하는 경험 입력 및 분석**입니다.
> Q&A 게시판이나 다크모드 같은 보조 기능은 **의도적으로 v2로 분리**했습니다.

---

### [p9] 사용 흐름 (15초)

> 사용 흐름은 **탐색 위주**입니다. 초기 기획은 글쓰기부터였지만, **강사님 피드백을 반영해** 메인 → 탐색 → 사례 조회 → AI 가이드 동선으로 바꿨습니다.
> 사용자가 서비스 목적을 이해한 후 자신의 경험을 분석하는 자연스러운 흐름입니다.

### [p11] 디자인 + BE (25초)

> 디자인은 **콘텐츠 중심 미니멀 UI**에 '선배의 조언' 보이스톤을 적용해 무거운 정보를 편안하게 전달합니다.
> 백엔드는 Spring Boot 기반으로, **카카오 로그인 중심 인증, 구조화된 경험 데이터 관리, AI 통합 분석 응답** — 세 가지 축으로 설계했습니다.

---

### [p12] AI 5단계 + 49 매트릭스 ⭐⭐ (35초) — 가장 중요

> AI 시스템은 **5단계로 설계**했습니다. 경험 입력 → 저장·요청 → 원인 분석 → 사례 매칭 → 리포트 제공.
> 강조드릴 점은 **자체 설계 IP**입니다.
> **5단계 전체 흐름 설계, SBERT + FAISS 매칭 로직 자체 구현, 49 가이드 매트릭스 직접 작성, advice 조합 로직, 100건 데이터 자동 태깅**까지 모두 자체 구현했습니다.
> **Claude API는 5단계 중 1단계 원인 분석에만 활용된 LLM 추론 도구로, 전체 시스템 핵심 로직은 자체 설계되었습니다.**

---

### [p13] KPI (15초)

> 북극성 지표는 **'탐색 후 의사결정 완료 사용자 수'**로 정의했고, 목표는 **1,000명**입니다.
> 재방문율, 사례 등록 전환율, AI 가이드 만족도 세 가지를 v2에서 측정할 예정입니다.

---

### [p14] 트러블슈팅 ⭐⭐ (30초)

> AI 모델 선택은 3주에 걸쳐 **세 번 피벗**했습니다.
> 3주차 **T5는 학습 한계로 폐기**, 4주차 **SBERT로 매칭만**, 5주차에 **한계를 인지하고 LLM API를 결합**해 5단계 통합 시스템을 완성했습니다.
> **저희는 LLM을 단순히 사용한 게 아니라, 한계를 인지하고 적합한 도구를 선택해 5단계 시스템에 통합했습니다.**

---

### [p15] 강사님 피드백 ⭐ (25초)

> **강사님 다섯 분의 피드백을 5개 영역 모두 운영에 반영**했습니다.
> PM 강사님의 글쓰기 허들 축소, PD 강사님의 데이터 신뢰성 보강, BE 강사님의 입력 정확성, AI 강사님의 5단계 격상, 클라우드 강사님의 배포 다이어그램 정비까지 **100퍼센트 반영**했습니다.
> 피드백을 듣는 것에 그치지 않고, 운영에 옮긴 팀입니다.

---

### [p16] 보안/배포 (20초)

> 6주간 **3회 배포**, 사전 심사 보안 체크리스트 5종 — HTTPS, Secret 관리, DB 외부 차단, SSH 포트 제한, 환경파일 미커밋 — **모두 100퍼센트 이행**했습니다.
> 프론트엔드·백엔드·AI 서버·데이터 저장소를 역할별로 분리한 **실제 운영 가능한 MVP 구조**입니다.

## 🎬 Q&A 예상 질문 (선택 — 시간 남으면)

1. **"Claude API에 너무 의존한 것 아닌가요?"**
   → "5단계 중 1단계 원인 분석에서만 LLM 추론 도구로 활용했습니다. 매칭은 SBERT+FAISS 자체 구현, advice 조합과 49 매트릭스는 BE 로직 기반으로 별도 LLM 호출 없이 자체 설계했습니다."

2. **"49건 데이터로 충분한가요?"**
   → "초기 49건에서 100건으로 확장했고, 자동 태깅 + JSON 검증 파이프라인을 구축했습니다. v2에서 SBERT+FAISS API 확장과 함께 데이터셋도 확대할 예정입니다."

3. **"T5는 왜 폐기했나요?"**
   → "T5는 fine-tuning 학습 데이터가 부족해 한계가 명확했고, 매칭에는 SBERT가 더 적합하다고 판단했습니다. 도구 선택의 의사결정 자체가 학습 과정이었습니다."

4. **"왜 카카오 로그인만 지원하나요?"**
   → "MVP 단계에서 진입 장벽 최소화 목적입니다. 국내 사용자 접근성이 가장 높은 OAuth로 카카오를 선택했고, 추후 구글·애플 로그인은 v2 확장 예정입니다."

5. **"북극성 지표 1,000명은 어떻게 측정하나요?"**
   → "현재는 자체 가설 단계입니다. v2에서 GA 또는 자체 분석 도구를 연동해 탐색→경험 입력→분석 결과 확인까지 완료한 사용자를 측정할 계획입니다."

6. **"FE는 누가 했나요? 정근원 BE인데?"**
   → "프론트엔드는 팀장인 저(오혜림)가 주도하고, BE 정근원 팀원이 통합 작업에서 일부 FE 작업을 함께했습니다. 인원 축소 상황에서 역할을 확장한 사례입니다."
