## 구간별 원고 포인트

### 1. 문제 정의

- 부업 정보는 성공 후기 중심으로 소비된다.
- 하지만 실제 사용자에게 더 필요한 것은 실패를 피하는 판단 기준이다.
- 실패담은 많아 보여도 구조화되지 않아 재사용이 어렵다.

### 2. 기존 대안의 한계

- 커뮤니티 글은 검색은 되지만 비교가 어렵다.
- 후기 콘텐츠는 감정적이고 맥락이 제각각이다.
- 사용자는 “그래서 나는 뭘 피해야 하는가”를 얻기 어렵다.

### 3. 해결책 소개

- Sidepick은 실패 경험을 구조화해 기록하게 만든다.
- AI가 실패 원인, 유사 사례, 다음 액션을 정리한다.
- 사용자는 단순 소비자가 아니라 실패 데이터를 학습 자산으로 활용하게 된다.

### 4. 데모

- 홈 또는 탐색에서 진입
- 사례 상세 확인
- AI 분석 리포트 확인
- 유사 사례 비교
- FAQ 또는 가이드 연결
- 필요하면 작성 플로우 소개

### 5. 기술 구조와 구현 범위

- 프론트: React + Vite
- 백엔드: Spring Boot
- AI 서버: FastAPI + Claude
- 유사 사례 탐색: SBERT + FAISS 자산
- 배포: Amplify + EC2 + RDS + Nginx

### 6. 차별점

- 실패 경험 자체를 1차 데이터 자산으로 본다.
- 단순 Q&A가 아니라 구조화된 탐색 경험을 제공한다.
- 기록, 분석, 비교, 가이드가 하나의 제품 루프 안에 있다.

### 7. 현재 성과와 다음 단계

- 라이브 MVP와 운영 배포까지 완료
- 핵심 사용자 흐름 구현 완료
- 다음 단계는 사용자 검증, 반복 방문 설계, 수익화 가설 정교화

## 발표 중 반드시 강조할 문장

저희의 핵심은 AI를 붙인 후기 서비스가 아니라, 실패를 다음 선택의 데이터로 바꾸는 제품이라는 점입니다.
