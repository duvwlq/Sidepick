# 데모 시나리오

## 데모 목표

- 사용자가 Sidepick을 왜 쓰는지 1분 안에 이해시키기
- 단순 게시글이 아니라 `실패 기록 -> AI 해석 -> 유사 사례 비교 -> 다음 판단` 흐름을 보여주기
- 실시간 AI 생성 지연 리스크를 최소화하기

## 권장 메인 시나리오

### 시나리오 A. 준비된 사례 상세 중심

1. 서비스 메인 또는 탐색 화면 진입
2. 특정 실패 사례 클릭
3. 사례 본문 핵심 읽기
4. AI 분석 리포트 확인
5. 유사 사례 비교
6. FAQ / 가이드 연결 확인
7. “이 서비스는 실패담을 읽고 끝나는 게 아니라 다음 판단 기준을 준다”로 마무리

## 발표용 멘트

### 오프닝

지금부터 Sidepick이 단순 후기 모음이 아니라 실패를 학습 자산으로 바꾸는 흐름을 어떻게 만드는지 보여드리겠습니다.

### 사례 상세 진입

먼저 사용자는 자신과 비슷한 실패 사례를 탐색하거나 바로 상세로 들어올 수 있습니다.

### AI 분석 구간

이 화면의 핵심은 원문을 그대로 보여주는 데서 끝나지 않고, AI가 실패 원인과 다음 액션을 정리해 준다는 점입니다.

### 유사 사례 구간

또 한 개의 사례만 보는 것이 아니라, 유사한 실패 패턴을 함께 비교하면서 사용자 판단 기준을 넓혀줍니다.

### FAQ 구간

그리고 사용자가 더 초반 단계라면 FAQ와 가이드로 연결해서 바로 행동 가능한 정보까지 이어집니다.

## 백업 시나리오

### 시나리오 B. 작성 플로우 소개

1. Create 화면 진입
2. 단계형 입력 구조 설명
3. “이렇게 구조화된 입력이 이후 AI 분석 품질의 기반이 된다” 설명
4. 상세 페이지로 복귀해서 결과 확인

### 시나리오 C. 탐색 / 검색 중심

1. 검색창 사용
2. 카테고리 필터 적용
3. 목록 결과 비교
4. 특정 사례 상세 진입

## 운영 팁

- 메인 데모는 `READY` 상태 사례 상세 기준으로 진행
- 실시간 생성은 보조 시연으로만 사용
- 네트워크 이슈에 대비해 화면 캡처를 슬라이드에 같이 준비
- 사례 ID나 URL은 발표 직전 실제 운영 상태로 다시 점검

## 발표자가 외워야 할 한 줄

저희 데모의 핵심은 기능 개수가 아니라, 실패 경험이 실제 판단 도구로 바뀌는 순간을 보여주는 것입니다.
